# Report: telling a broken sensor from a lying one

*Detection and attribution of false data injection versus physical sensor faults in a synthetic
GNSS/INS navigation chain, across attack sophistication, with honest limits.*

Every number below is generated by a script in [`validation/`](../validation/) and copied from
[`validation/results/`](../validation/results/). The course in [`lessons/`](lessons/README.md)
derives each method.

## 1. Summary

* A competent, cause-blind anomaly detector (Isolation Forest on generic features) reaches ROC
  AUC 0.85 and detects 75 % of physical faults but only 35 % of false data injections. Its score
  ranks faults *above* attacks: as a test of "attack, not fault" its AUC is 0.197.
* Physics residuals change that. A gradient-boosting classifier on 52 residual summaries
  attributes 99 % of faults correctly and recognises 99 to 100 % of naive, single-channel and
  statically consistent attacks (L0 to L2) as FDI. Among flagged anomalies the cause is right
  99.9 % of the time. A fully consistent drag-off (L3) is called normal 99.2 % of the time.
* Along a continuous stealth dial, a classifier trained on crude attacks loses attribution at
  $s = 0.8$ (static path) and $s = 0.9$ (dynamic path). Adding Kalman-filter consistency features
  removes the static breakdown and moves the dynamic one to $s = 1$.
* An attacker who reproduces a fault's effect exactly is attributed to a fault every time, as
  Bayes' rule says any classifier must.
* The navigation integrity check's miss probability, which CPS-02 assumed to be 0.1 for GNSS
  spoofing, depends on the monitor and the attacker's reach: 0 for crude attacks, 0.03 (with the
  inertial witness) to 0.51 (snapshot check) for receivers-only spoofing, about 1 for a bus-level
  consistent injection.
* A dissimilar sensor out of the attacker's reach protects exactly the directions it observes: a
  protected baro exposes every vertical bus-level drag-off and no along-track one.
* On the IEEE 14-bus system, the same estimator code reproduces the stealthy-attack theorem
  (residual change $5 \times 10^{-15}$) and the noncentral detection law (0.461 closed form, 0.463 Monte Carlo).
* On the public HAI testbed, data-driven versions of the two consistency checks catch all 5 attack
  events of test1 and 15 of 20 of test2 (per-second AUC 0.83 to 0.93); the longest false alarm is an
  operating point outside the training data.

## 2. Problem and system

The correct response to a wrong sensor reading depends on its cause: maintenance for a failing
unit, incident response for manipulated data. The system is the synthetic navigation chain shared
with CPS-01 and CPS-02: two embedded GNSS/INS units feeding a mission computer over a data bus, plus
a dissimilar barometric altitude added here. Telemetry has 13 channels at 1 Hz over 300-s segments.
Physical faults (bias, drift, stuck, noise, a shared receiver error) and FDI at four levels (naive,
plausible, statically consistent, dynamically consistent) are injected with ground truth by
construction. Scope and boundaries: [`scope.md`](scope.md).

## 4. Implications

* **For the CPS series.** In CPS-02 the integrity-monitor miss leaf (0.1) gates only the GNSS
  spoofing path; the bus-injection path has no detection leaf, so injected messages are always
  accepted. The measurements refine both. Against receivers-only spoofing the miss probability is
  0.51 with a snapshot cross-check and 0.03 with an INS-aided filter and consistency features, so
  0.1 is optimistic for the first monitor and pessimistic for the second. On the bus path, the
  Kalman filter catches every crude injection (L0 to L2) and misses only the fully consistent L3,
  so "always accepted" holds only for the most capable attacker. The same numbers would feed
  CPS-01's availability model through its integrity scenarios.
* **For design.** Detection cannot see an injection that is a trajectory of the system's own model.
  The remedy is architectural: an independent source per state direction, on a path the attacker
  cannot write to. The inertial sensors are such a witness against an RF spoofer, but not against a
  bus-level attacker.
* **For operations.** A strong fault-versus-attack classifier is only as good as its fault model and
  its training attacks. Its output should be a prior for the response team, not a verdict.

## 5. Limits

* **Synthetic system.** Noise levels, fault ranges and attack magnitudes are stated assumptions.
  Absolute rates are conditional on them; the closed-form limits and the comparisons are what
  transfer.
* **Simplified sensors.** White noise, a loosely coupled position/velocity model, two axes, 1 Hz.
  Real GNSS errors are time-correlated, which would change thresholds and some detection rates.
* **Attribution is only measured on synthetic data.** No public data set used here labels physical
  faults.
* **Attacker habits.** Part of the classifier's success against L1 comes from assumed offsets and
  ramp-ins (Lesson 3, Section 6); the mimicry experiment shows the cost when they are dropped.
* **HAI measures.** Per-second and per-event measures only; the dataset's authors recommend eTaPR,
  not computed here. Only one of HAI's three training files was used.
* **Novelty.** The theorems used are known; the contribution is the evaluation and its link to the
  reliability and attack-tree models ([`related-work.md`](related-work.md)).

## 6. Reproducibility

`uv run python validation/run_all.py` regenerates every table. CI reruns it on every push and fails
if any table changes, except the CNN's, which is checked within a tolerance of 0.03 because CPU
kernels can differ between machines; the HAI script runs only where the dataset has been fetched.
